auto-decide Detailed Architecture 把现有数学骨架整理成可执行的架构、需求、任务拆分和 refine 路线

scope: auto_decide/ + docs/ focus: architecture / requirements / task breakdown / refine target readers: implementer / reviewer / SRE
What this is 这是一张“能开工”的架构图，不是摘要。 它回答四个问题： 1. 系统有哪些稳定层和边界； 2. 每层必须满足什么需求； 3. 这些需求如何拆成任务； 4. 哪些点需要按指标持续 refine。

1 · Architecture

当前系统遵循一个固定原则：名义建议可以智能，硬边界必须可证。 因此架构被切成三类层次：

  • Sense / model layer：`graph.py`、`dynamics.py`、`potential.py`、`game.py`、`reachable.py`，负责把场景、状态、不确定性和未来可达性表示出来。
  • Safety layer：`lyapunov.py`、`cbf.py`、`invariant.py`，负责把“能不能过”和“能否持续稳定”从智能建议里剥离出来。
  • Orchestration layer：`planner.py`，把所有东西串成唯一入口，并把 `trace` 变成全系统的真相源。

2 · Requirements

要求分两层：功能要求描述系统必须做什么，非功能要求描述它必须以什么质量做。 所有要求都要能落回代码、测试和 trace。

2.1 Functional requirements

IDRequirementMapped moduleAcceptance
FR-01Build a time-varying intent graph from scene observations.graph.pyEdge weights increase when distance shrinks and conflict grows; graph stays directed.
FR-02Propagate ego state with jerk-driven bicycle dynamics and clamp the friction envelope.dynamics.pyStraight motion is numerically stable; |a| ≤ μg always holds.
FR-03Produce a soft nominal direction from the composite potential field.potential.pyGoal pulls, obstacles repel, interaction term adds pressure only.
FR-04Expose a Lyapunov monitor for velocity tracking stability.lyapunov.pydV_dt ≤ 0 in cruising; trace exposes V and dV_dt.

FR-06Filter nominal action through CBF constraints into the nearest feasible command.cbf.pyUnsafe nominal action is converted to safer action or fallback brake.
FR-07Wrap the filtered action in T_inv with relaxation and bounded fallback.invariant.pyFinite steps only; no exception leak; emergency brake always feasible.
FR-08Expose a single-step planner entry that emits control and trace.planner.pyNo external caller can bypass T_inv and call executor directly.
FR-09Expose trace and metrics suitable for automated review and offline debugging.planner.py + docsTrace schema contains state, control, stability, safety and status fields.
FR-10Provide a migration seam to SRE vocabulary without changing the math core.sre-adaptation.htmlEach pattern can be mapped to a named SRE concept.

3 · Task Breakdown

任务拆分按“先稳骨架，再补边界，再装配，再迁移”的顺序做。 这样可以避免把所有不确定性一次性叠加到同一条 PR 上。

PhaseTaskDepends onDeliverableRefine lever
P0Freeze types, units and public API.nonetypes.py and contract docsReduce shape drift
P1Finish graph and dynamics as stable front-end models.P0Graph update, clamp, RK4, feasibility testsFix unit and direction errors
P2Wire potential, Lyapunov, reachable and game layers.P1Nominal policy + stability monitor + dead-zone heuristicSeparate soft and hard constraints
P3Ship CBF and T_inv as the hard safety path.P2Safe control filter with bounded fallbackTighten safety margin and relative degree handling
P4Assemble planner and trace schema.P3Single-entry `step()` with JSONL traceMake review and replay deterministic
P5Build demos and regression benches.P4Intersection demo and structural-vs-e2e benchmarkObserve real failure modes
P6Map the same skeleton to SRE.P5`sre-adaptation.html` / future `sre_control/` packageTranslate patterns, not math

3.1 Critical path

  1. types.py -> graph.py -> dynamics.py
  2. potential.py -> lyapunov.py -> reachable.py
  3. game.py -> cbf.py -> invariant.py
  4. planner.py -> trace -> demo / benchmark / CI
  5. sre-adaptation.html as the migration seam, not the blocker

3.2 Parallelizable side work

  • Update docs and formula index in parallel with unit tests.
  • Prepare trace schema and benchmark scenarios while core safety layers mature.
  • Draft SRE mappings early so the adapter does not drift from the math core.
Ordering rule 不要先优化 nominal policy 再补硬边界。 先把 `CBF` / `T_inv` 的下界做稳，再把智能部分放进去，否则 refine 的方向会被错误建议污染。

4 · Refine

Refine 不是“把参数调大调小”这么简单，而是一个围绕指标、失败模式和边界合同的循环。

4.1 Symptom -> refine target

SymptomRefine targetTypical moveExpected effect
Penetration or near-penetrationcbf.py / barrier modelIncrease safety margin, fix relative degree, raise h_dot horizonFewer safety violations
Too many emergency brakesgame.py + nominal policyRefine belief-derived margin, improve nominal predictionLower false alarms while staying safe
Stability check often failslyapunov.py / invariant.pyKeep V as pure speed-tracking term; relax jerk step sizeMore stable cruising
Planner latency too highcbf.py search strategyReplace grid search with true QP, cache invariantsLower P99 latency
Trace missing or ambiguousplanner.py + schemaLock fields, add JSON schema, add regressionReview becomes deterministic
Bypass risk appearsAPI boundaryEnforce single entry and static grep rulesNo silent hard-constraint bypass
SRE mapping feels forcedsre-adaptation.htmlTranslate mechanism, not surface labelsMigration remains faithful

4.2 Refine priorities

  1. Keep hard constraints hard. Do not smooth away `CBF` or `T_inv` into losses.
  2. Improve the approximation order next. Move from heuristic grid to real QP only after the boundary is trusted.
  3. Wire dynamic uncertainty last. Belief-based derating should widen or shrink margin, not replace the gate.
  4. Refine observability continuously. Trace fields are part of the contract, not a debug afterthought.
  5. Refine by scenario. Rain, high speed, close obstacle, non-cooperative agent, and OOD intent should each have a dedicated regression.
Refine rule for SRE transfer Port the pattern, not the metaphor. If the auto-decide side says "CBF", the SRE side should say "admission controller"; if the auto-decide side says "Lyapunov", the SRE side should say "bounded burn rate"; if the auto-decide side says "T_inv", the SRE side should say "change guard".
