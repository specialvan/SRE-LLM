2 · 原文结构化摘要

原文 4 节的提纲式改写，每节只保留对工程实现有决定性影响的断言。

2.1 §1 核心结构 —— 时变非线性流形上的受限梯度流

原文的关键转向：把自动驾驶从"感知到控制的端到端回归问题"重新建模为 离散层（意图博弈）与连续层（动力学流形）耦合的结构化问题。

  • §1.1 离散层：$G_I = (V_I, E_I)$，边权描述的是 意图冲突强度，不是几何距离。
  • §1.2 连续层：状态 $x = (p_x, p_y, \psi, v, a, \mu)$，动力学 $\dot x = f(x,u)$，轮胎约束 $|a|\le\mu g$ 把空间切成非欧流形。
  • §1.3 耦合：决策 = 在势能场 $\Phi$ 中做受限梯度流 $\dot x = -\nabla\Phi(x)$，受限意味着投影回流形切空间 / 可行集。
SRE 视角 这一节定义了"问题本身"的边界，工程上意味着系统必须把"意图"作为一等公民。纯几何的避障（ACC / AEB）只对应连续层， 一旦进入多智能体博弈场景就会失稳——这是 SLO 选型时选择"结构化决策"而不是"纯端到端"的数学依据。

2.2 §2 数学边界 —— Lyapunov / 可达集 / 博弈

原文列出了决定系统"能干什么"的三类硬边界：

类别公式物理含义越界后果
物理不变量 $\dfrac{dV(x)}{dt}\le 0$ 能量函数单调不增 正反馈失控，任何算法无法挽回
拓扑边界 $\mathcal{R}(x_0,T)$ 执行器能力封闭的可达集 逻辑死区：撞击不可避免
信息边界 纳什均衡下的安全冗余 缓冲区必须足以吸收他人最坏意图 概率型预测失败时事故

2.3 §3 优化空间重构 —— 结构生成算子

原文主张把搜索从"权重空间"挪到"安全空间"：

  • §3.1 $T_\text{inv}$：$u_\text{safe} = T_\text{inv}(u_{nn})$，强制 $\dot V \le 0$。
  • §3.2 CBF：$h(x)\ge 0 \wedge \dot h(x,u) + \alpha h(x) \ge 0$，几何上"拓扑栅栏"，优化上"搜索空间折叠"。
  • §3.3 定量对比：长尾 OOD 场景，碰撞率较端到端降 2~3 个数量级。本工程的基准复现结果是 28% → 0%（在可恢复的场景集上，见 examples/compare_e2e_vs_structural.py）。

2.4 §4 结语 —— 给 AI 戴上物理的枷锁

原文落脚到一个经典的工程哲学断言：AI 负责灵活性，物理不变量负责可控性。 落地为代码就是：任何神经网络输出，必须先过 T_inv.apply 才能写到线控——这一点是本工程最不可妥协的约束，也是 SRE 评审的首要 Guardrail（见 §6.2 风险 R-01）。

3 · 系统总架构图

下图是 StructuralPlanner.step(obs) 一次控制循环的完整数据流。黄色闸门是硬约束检查点； 绿色是可学习 / 可替换模块；红色是降级出口。

SRE 约束 该架构有 4 个不变式必须在任何提交里保持：
  1. ①→④ 之间不得反向引用 ⑦（循环依赖会把降级路径拖入）；
  2. ④ 的任何输出必须经 ⑥ 再 ⑦（顺序不能换，CBF 折叠可行集、Tinv 才能在折叠后的集上做 Lyapunov 投影）；
  3. ⑦ 失败时唯一合法出口是 ⊗（Control(0, -jerk_max)），不得由 ④ 再尝试；
  4. ⑨ 的写入不得阻塞主环（异步队列或采样写）。

4 · 模块级深度拆解

每个模块按同一结构展开：机制 → 关键公式 → 实现选择 → 参数清单 → 复杂度 / 时延 → 失败模式 → SRE 要点。 这样 Codex 可以按固定字段扫描。

4.1 模块 1 · 交互意图图 G_I = (V_I, E_I)

机制：把交通环境中每个参与者抽象成节点，每条边不仅有几何关系还带 意图冲突 语义。 "距离近" 只是必要条件；真正决定相互影响强度的是"我想做的事和你想做的事是否冲突"。

关键公式

单条有向边 $i\to j$ 的权重：

$$ w_{ij} = \underbrace{\exp\!\left(-\frac{\|p_j - p_i\|}{D_0}\right)}_{\text{距离核 } g(d)} \cdot \underbrace{\tfrac12\left(1 + \cos\theta_{ij}\right)}_{\text{朝向修正}} \cdot \underbrace{\mathbb{E}_{a\sim p_i,b\sim p_j}[C(a,b)]}_{\text{意图冲突概率}} $$ 其中 $\theta_{ij} = \angle(v_i,\, p_j - p_i)$，$C(a,b)$ 是意图冲突表。

实现选择

  • 距离核用指数而非 $1/d$：保证边权在 $[0,1]$、连续、边界不发散。
  • 冲突表是"手工先验"：原文没规定形式，这里用小的字典（graph._CONFLICT_TABLE）。上层感知如果能给更好的分布，可以注入。
  • 每帧重建而非增量更新：场景规模小（≤100 agents）时重建更稳，避免陈旧边。

参数清单

参数含义默认影响
D0距离核尺度 (m)15.0越大相互作用辐射越远；实测 10-20m 合理
EPS边权过滤阈1e-3影响图稀疏度与下游势能计算开销
_CONFLICT_TABLE意图冲突先验手工上层感知若能注入，应替换

复杂度 / 时延

$O(n^2)$，$n$ = agent 数。100 agents 实测 < 1 ms（纯 Python）。大于 1000 agents 需要改 KD-tree 剪枝。

失败模式

  • 意图分布误差放大：若上层预测意图概率跳变（比如感知 flicker），$w_{ij}$ 会震荡，下游势能梯度跟着抖。缓解：对 $p_i$ 做 EMA 平滑。
  • 障碍物作为静态节点权重恒定：静态障碍没有意图，需要走 CBF 通道（见 §4.6），不在 $G_I$ 里纠缠。
SRE 指标：graph.edges_count、graph.update_ms（P50/P99）、graph.intent_flicker_rate（每秒意图主模式翻转次数）。 Alert：intent_flicker_rate 连续 3s > 2 Hz 表示上游不稳，此时下游应停止根据 $G_I$ 做激进决策（fall back 到纯几何）。

4.2 模块 2 · 车辆动力学 ẋ = f(x, u)

机制：在连续层建模一辆车的物理行为。用运动学 bicycle 模型加 jerk 驱动——这样每个命令都是连续可导的， barrier 函数求梯度时不会出现台阶。轮胎摩擦 $|a|\le\mu g$ 在 $f$ 和 step 两处同时 clamp，保证数值上永远不越界。

关键公式

$$ x = (p_x, p_y, \psi, v, a, \mu)^\top,\quad u = (\delta, j)^\top $$ $$ \dot x = f(x,u) = \begin{pmatrix} v\cos\psi \\ v\sin\psi \\ (v/L)\tan\delta \\ a \\ j \\ 0 \end{pmatrix},\quad |a| \le \mu g $$

为什么选 jerk 而不是 acceleration？

CBF 在第二阶动力学上是"相对度 2"的，意味着 $u$ 不直接出现在 $\dot h$ 里，单次 QP 无法拦截高速接近。把 $a$ 从状态拿出、让 $j$ 作为输入， 就能让距离类 barrier 变成相对度 1（通过 刹车距离 barrier，见 §4.6）。这是工程上与纯书本模型的关键差异。

参数清单

参数默认说明
wheelbase L2.8 m普通乘用车
max_steer35°转向上限
jerk_max6.0 m/s³电子线控典型值
v_max35 m/s限速硬上限
μ作为状态来自感知：干燥路面 ≈ 1.0；雨天 ≈ 0.5；冰面 ≈ 0.2

失败模式

  • μ 感知错误：下游所有屏障都依赖 μg，如果 μ 被高估，刹车距离被低估，CBF 允许更晚减速——首要风险。 缓解：用 safety=0.6 的 derating（见 BrakingDistanceBarrier._a_brake）。
  • RK4 vs 真实车辆：kinematic 模型忽略侧偏，高速大转向时有 1~2% 轨迹误差。在仿真中 OK，上车前必须换成 dynamic bicycle。
SRE 指标：dyn.step_ms（应 < 0.1 ms），dyn.mu_estimate（连续性采样），dyn.a_clamped_rate（clamp 次数/秒）。 a_clamped_rate 上升意味着执行器被物理约束，planner 可能已进入逻辑死区（见 §4.5）。

4.3 模块 3 · 势能场与受限梯度流

机制：把"到目的地"、"躲障碍"、"守规则"合成一个标量场 $\Phi$。 期望车的轨迹沿 $-\nabla\Phi$ 流动，但要在可行流形的切空间里——这就是"受限梯度流"。

三项分解

$$ \Phi(x) = \underbrace{\tfrac12 w_g \|p - p_g\|^2}_{\text{吸引项}} + \underbrace{w_o \sum_{o\in\mathcal{O}} \left(\frac{r_s}{d_o(p)} - 1\right)^2 \mathbb{1}[d_o < r_s]}_{\text{排斥项}} + \underbrace{w_i \sum_{j\in N_\text{ego}} \frac{w_{ij}}{\max(d_{ij}, 0.5)}}_{\text{交互项}} $$

$d_o$ 是到障碍的符号距离，$r_s$ 是安全半径。三项都是显式解析的，梯度默认用数值差分（2D 有限差分 < 50 μs）。

实现选择

  • 排斥项用 $(r_s/d - 1)^2$ 而不是 $1/d^2$：有限支集，不会影响远处的梯度，数值稳定。
  • 梯度用前向差分：$\mathcal{O}(\text{components})$ 求值两次，在 2D 平面上成本极低。上车前可改解析梯度。
  • 交互项用 $w_{ij}/d_{ij}$：距离近且博弈权重大的邻居贡献最强。

参数清单

参数默认物理含义
w_goal1.0吸引强度
w_obs10.0静态障碍排斥强度
w_interact5.0动态他车影响强度
safety_radius r_s2.5 m排斥场作用范围
坑 局部极小值：势能法天然会卡在 U 形障碍后。这里靠上层的 CBF + 可达集兜底，不指望 Φ 独自规划。 如果一帧 Φ 梯度接近 0 但离目标仍远（‖∇Φ‖ < 1e-3 且 ‖p-goal‖ > 5m），必须上报"规划停滞"。

4.4 模块 4 · Lyapunov 稳定性

机制：选一个能量函数 $V(x)$，让它沿系统演化单调不增。原文强调 $V$ 是"物理红线"：任何导致 $\dot V > 0$ 的控制输入都被拒绝。

关键工程决策 代码里的 $V$ 只包含速度跟踪项，不包含距离项——与原文里语言上的"安全势能函数"略有区别。 原因：把"稳定 = 能跟踪目标速度"与"安全 = 不碰障碍"解耦，各自归 Lyapunov 和 CBF 两个不同数学工具。 合并会导致走向目标的每一步都触发 V 上升，出现"连刹不前"的病态行为（我们在第一版实现里真踩过这个坑）。

关键公式

$$ V(x) = \tfrac12 q_v (v - v^*)^2,\qquad \frac{dV}{dt} = q_v (v-v^*)\cdot a $$

硬约束：$\dot V(x, u) \le 0$（数值形式：$(V_{t+dt} - V_t)/dt \le \tau$，$\tau = 10^{-3}$）。 优先形式（指数衰减）：$\dot V \le -\gamma V$，$\gamma = 0.5$。

数值实现细节

  1. dV_dt 用前向差 $dt = 0.01$ s；太小看不到 jerk 的累计效应，太大损失精度。
  2. check(state, u) 返回 (is_stable, dV_dt)——必须两个值都返回，SRE 的 metrics 需要实际值而不仅布尔。
  3. $V$ 只随速度误差平方增长 → $V_\max = \tfrac12 q_v v_{\max}^2 \approx 613$（$v^* = 0$, $v_\max = 35$），可以作为归一化基准。

失败模式

  • target_speed 漂移：如果上层 $v^*$ 跳变，Lyapunov 会忽然鼓起，触发一串 T_inv 矫正 → 体感 = 点刹。缓解：$v^*$ 要经过限幅器（$|\Delta v^*| \le 2 $m/s/每周期）。
  • 数值 $\dot V$ 抖动：低速时 $v - v^*$ 很小，有限差信噪比低。可对 $\dot V$ 做 5 点中值滤波。
SRE 指标：lyap.V、lyap.dV_dt、lyap.tinv_intervene_rate。 Alert：tinv_intervene_rate > 20% 持续 10 s 表示 NN 策略与物理边界严重不匹配——应切换到更保守的名义策略。

4.5 模块 5 · 可达集 R(x₀, T)

机制：给定当前状态 $x_0$ 与时间窗 $T$，枚举所有可行控制序列的终点，形成可达集。 当外部不确定性（前车急刹、行人闯入）的位置落在可达集外，就意味着"无论怎么开都躲不过"——即"逻辑死区"。

关键公式

$$ \mathcal{R}(x_0, T) = \left\{ \phi(T; x_0, u(\cdot))\;\middle|\; u(t) \in \mathcal{U},\, t \in [0, T] \right\} $$

工程上用采样 + 凸包近似：随机生成 $N$ 条分段常值控制序列，各自 RK4 积分到 $T$，取终点；取终点的凸包作为可达区域。

参数与复杂度

参数默认影响
horizon T2.0 s越长可达集越大，但计算越慢
n_samples200终点采样数，权衡覆盖 vs 时延
dt0.1 s积分步长

复杂度 $\mathcal{O}(N \cdot T/dt)$，200×20 次 step，实测 < 5 ms。不在每帧主环里跑——只在"感知到显著威胁"时触发（事件驱动）。

失败模式

  • 凸包高估：真实可达集通常是非凸的（U-turn 受限），凸包会把一些"达不到"的点也算进去——乐观偏差。需要用"凹补集"或 HJ reachability 更严谨。本版本够用于 dead-zone 保守下界。
  • 采样偏置：当前用均匀采样控制序列，覆盖度有限。可换成 Sobol 或 LHS 以更均匀。
SRE 指标：reach.sample_ms、reach.dead_zone_rate、reach.hull_area。 触发条件（事件驱动）：出现速度差 > 15 m/s 的他车 / 检测到突发障碍 / μ 突降。

4.6 模块 6 · 控制屏障函数 CBF

机制：定义安全集 $\mathcal{C} = \{x \mid h(x) \ge 0\}$，再通过不等式 $\dot h + \alpha h \ge 0$ 保证前向不变。 这是把"软安全建议"变成"硬安全约束"的数学桥。本工程提供 两类屏障：纯几何（distance）与刹车距离（braking distance）。

两类屏障对比

DistanceBarrierBrakingDistanceBarrier
$h(x)$ $d_\text{obs}(p) - r_s$ $d_\text{obs}(p) - r_s - v\tau - \dfrac{v^2}{2 a_\text{brk}(\mu)}$
对 jerk 的相对度2（不够灵敏）1（可即时矫正）
适用静态边界（车道线、停车线）高速动态避障
μ 自适应✗✓ $a_\text{brk}(\mu) = 0.6 \min(a_\text{max}, \mu g)$

CBF-QP 求解

$$ \begin{aligned} \min_u \quad & \|u - u_\text{nom}\|^2 + \rho\, \delta^2 \\ \text{s.t.} \quad & \dot h_i(x, u) + \alpha h_i(x) \ge -\delta \quad \forall i\\ & u \in \mathcal{U},\; \delta \ge 0 \end{aligned} $$

本工程没拉 QP 求解器依赖，而是用 粗网格 + 精化网格 的两步搜索（详见 cbf.CBFQPFilter.filter），在 2D 输入上毫秒级收敛。上车需要替换为 OSQP / qpOASES。

参数清单

参数默认说明
alpha3.0类 K 函数增益，越大反应越"急"
rho1e3松弛罚因子，越大越接近严格 QP
h_dot_horizon0.1 s有限差分前瞻，必须大于 jerk ramp 时间
reaction τ0.35 sCBF 中反应时间缓冲
a_max_brake6.0 m/s²保守刹车上限
safety0.6μ derating

失败模式

  • $\alpha$ 过小：系统反应迟钝，可能在动态障碍面前失效。
  • $\alpha$ 过大：名义策略稍有动作就触发"急刹点头"，体感差。
  • barrier 数量过多：QP 维度 = $n_\text{barrier}$，当障碍 > 30 时网格搜索会变慢。上车需要改真 QP。
SRE 指标：cbf.filter_ms、cbf.fallback_rate（降级刹停次数 / 总步数）、cbf.active_barriers。 Alert：fallback_rate > 5% 10 s 表示 QP 长期不可行，名义策略必须立即收紧（减速 / 加大缓冲）。

4.7 模块 7 · 控制不变集算子 T_inv

机制：原文 §3.1 的核心算子。输入任意神经网络 / MPC 的候选命令 $u_{nn}$，输出满足 Lyapunov 硬约束的 $u_\text{safe}$。 这是整个系统最不可降级的组件——所有下游执行器命令都必须过这个算子。

三段流水

  1. CBF 折叠：先让候选命令穿过 CBFQPFilter，剪掉所有违反 $\dot h + \alpha h \ge 0$ 的动作。
  2. Lyapunov 松弛：若 CBF 输出仍然令 $\dot V > 0$，按步长 $\Delta j = j_\text{max}/N$ 迭代降 jerk，直到 $\dot V \le 0$（优先 $\dot V \le -\gamma V$）。
  3. 降级兜底：松弛 $N$ 步后仍无解则退到 Control(0, -jerk_max)，告警 + 记录。

状态机

T_inv.apply 会返回一个 status ∈ {stable, non_increasing, relaxed, relaxed_exp, emergency_brake}，含义：

  • stable：首次尝试即满足 $\dot V \le -\gamma V$（最佳）；
  • relaxed_exp：松弛后满足指数衰减目标；
  • relaxed：松弛后只满足 $\dot V \le \tau$（退回普通 Lyapunov）；
  • non_increasing：恰好在容差内，边缘稳定；
  • emergency_brake：兜底，应触发告警。

正确性证明要点（评审提示）

  1. 降级命令 Control(0, −j_max) 永远满足可行集（不违反转向约束、符合摩擦上限），QP 可行性保证终止。
  2. 松弛方向单调降 jerk → $V$ 的关于 $u$ 导数为 $q_v(v-v^*)\cdot \partial a / \partial j = q_v(v-v^*)\cdot dt$，方向单调正相关 → 单调下降。
  3. 最多 $N=8$ 次迭代后 jerk 达到下限，算法必然终止（有限步）。
SRE 指标：tinv.status_count{stable|relaxed|relaxed_exp|emergency_brake}。 emergency_brake 占比 > 2% 持续 30 s → P1 告警，名义策略需要更保守。

4.8 模块 8 · 非完全信息博弈 / 安全冗余

机制：原文 §2.3 的落地。他车意图不可观测时，planner 对"最坏情况"做兜底——把 CBF 的安全半径 $r_s$ 按置信度熵放大。 这让"我不知道你要不要转"自动翻译成"那我就多留出一车位"。

关键公式

$$ \begin{aligned} H(p) &= -\sum_k p_k \log p_k,\quad \eta = H(p)/\log |p| \in [0,1] \\ r_\text{buf} &= r_\text{base} + k_v \max(0, v_\text{close}) + k_\eta\, \eta \end{aligned} $$

$\eta$ 是归一化意图熵；$v_\text{close}$ 是闭合速度。对多个他车取 max（最坏情况聚合）。

与 CBF 的耦合方式

这个模块不直接出控制命令。它把 $r_\text{buf}$ 写到 make_obstacle_barriers(margin=r_buf) 的参数里—— 他车的 barrier 会按当前置信度做几何膨胀。这样博弈层的不确定性就被"代数化"成 CBF 约束的一部分， 单元测试只需要验证"输入熵→输出缓冲"的单调性，不需要联调。

参数清单

参数默认影响
base_buffer r_base3.0 m最小安全距离
speed_gain k_v1.2 s每 m/s 闭合速度加多少 m 缓冲
entropy_gain k_η2.0 m完全不确定时的额外缓冲

失败模式 & 讨论

  • 非真正的纳什均衡：本实现是"保守启发式"，不是真的求解对抗 game tree。实测在 Highway/Intersection 场景足够安全，但对"反复博弈让行"之类微妙交互不能最优响应。
  • 熵爆炸：意图分布极端均匀（感知失灵）时 $r_\text{buf}$ 会冲高，触发 Planner 连续减速——等价于"感知不信任时先慢下来"，体感对，安全对。
SRE 指标：game.buffer_p50/p99、game.entropy_mean。 Alert：game.entropy_mean > 0.9 持续 5 s → 感知上游可疑，上报数据质量问题。

4.9 模块 9 · Planner 主循环

机制：把前面 8 个模块装配成一个 step(obs) → (state, u_safe, trace)。这是外部唯一调用入口。 组装顺序由 §3 的 SRE 不变式约束：graph → potential → game → nominal → cbf → T_inv → dynamics.step → trace。

6.5 参数治理

本工程全部参数（约 25 个）集中在三个类：VehicleParams / PotentialField / CBFQPFilter / QuadraticLyapunov / ControlInvariantOperator / WorstCaseGame。 治理原则：

  1. 车辆物理参数（VehicleParams）是车型级常量，由整车配置文件发下；禁止代码硬编码。
  2. 控制 tuning 参数（alpha, gamma, q_v）走影子发布（shadow deploy），对比 7 天 trace 指标后才允许上线。
  3. 安全边界参数（safety, reaction, base_buffer）任何下调需要双人评审 + 记录在 PARAM_CHANGELOG.md。
  4. 参数单元：所有涉及时间的单位是秒，距离是米，角度是弧度——注释中明示；评审时 Codex 应扫描带"rate/time"而单位不明的参数。
类别变更策略回滚时间
车辆物理（L / v_max）随整车 OTA需要整车重启
控制 tuning影子 → 灰度 5% → 50% → 100%< 5 min
安全边界仅保守方向自动，放宽方向手动< 1 min（配置中心热更）

6.6 发布与演进路线

从研究原型到量产的路径：

  1. Milestone 1 · 仿真闭环（当前）：examples/* + pytest 全通；benchmark E2E 28% → 结构化 0% 碰撞率。
  2. Milestone 2 · QP 替换：把网格搜索换成 OSQP，P99 压到 < 3 ms。
  3. Milestone 3 · dynamic bicycle：引入侧偏动力学，适配 > 80 km/h 场景。
  4. Milestone 4 · HIL（硬件在环）：在实车 ECU 上跑 10⁶ 公里仿真，安全 SLO 达标。
  5. Milestone 5 · 数据触发式升级：收集实车 trace，对名义策略做 imitation learning；T_inv 保持不变作为安全基座。
禁止事项 演进过程中不得把"让 NN 直接输出 u_safe 绕过 T_inv"作为"优化项"——这是结构生成算子的本质约束， 任何删除或弱化 T_inv 的 PR 必须被 reject。
