7 个 stage 的契约（纯度 / 降级 / 可观测）

Stage输入关键输出降级策略
stage.pcatelemetry fused, hidden_norm fit 失败 → fused = mu
stage.synergy依赖图 score 图太小 → score = 0
stage.adjusted_probsstreak + 候选 probs, k_factor 不降级（极少异常）
stage.entropyprobs acceptable_idx, fallback_used 空集 → argmax-H 兜底
stage.eommhistory + 候选 source = "artifact" | "fallback" artifact 异常 → 切 fallback 规则
stage.risk6 维风险特征 prob, level Cox 异常 → prob=0.5, level=warn
_resolve_decision所有上游 DecisionKind 纯策略，不允许数值计算

策略表（_resolve_decision 的心脏）

risk_level == ALARM
  ├── loss_streak >= 2 → ROLLBACK
  └── else              → HOLD

risk_level == WARN      → CANARY

risk_level == OK
  ├── confidence < 0.5                        → CANARY
  ├── tier==critical && strategy!="canary"     → CANARY (downgrade)
  ├── strategy == "full"                       → GO
  ├── strategy == "canary"                     → CANARY
  ├── strategy ∈ {"shadow","holdback"}         → HOLD
  └── unknown strategy                         → ESCALATE

关键契约

改这张表的任何一条必须：开 ADR、加 replay fixture、走 shadow→advisory→enforce 推进。 参见 08-rollout-and-governance.md。

4. 九机制 → SRE 控制原语 迁移抽象

九个机制的 真正工程价值 不是"算法列表"，而是可被其它 SRE 控制面复用的能力目录。

TrueSkill production

belief_state_estimator

把每次发布结果变成带不确定度的 $(\mu, \sigma)$，不是点估计。

Stage: observe_release · 可迁移到服务健康评分、inspection 节流、auto-rollback trust。

EOMM mixed

objective_aware_strategy_ranker

按"保留 SLO 目标的期望"对候选策略排序，而非纯预测胜率。

Stage: stage.eomm · 可迁移到 rollout 策略、告警路由、remediation 选择。

Dynamic K production

adaptive_gain_scheduler

连续成功时降低更新步长，防止过度自信。

Stage: stage.adjusted_probs · 可迁移到 auto-tuning、自适应 rollout 大小。

PCA production

latent_signal_compressor

多维 telemetry → 单个可审计的压缩分。

Stage: stage.pca · 可迁移到 anomaly pre-filter、alert 聚类、metric bundle 摘要。

GNN mixed

graph_blast_radius_scorer

让依赖图和共同发布历史影响本地风险打分。

Stage: stage.synergy · 可迁移到依赖感知的发布门、容量变更风险。

Handicap production

risk_adjusted_probability_scorer

用上下文 penalty 把乐观的胜率拉回"有担心值"。

Stage: stage.adjusted_probs · 可迁移到 canary 大小调整、变更风险打分。

Entropy production

information_value_gate

拒绝"过于确定"的候选（canary 结果已经能预测 = 没信息量）。

Stage: stage.entropy · 可迁移到 synthetic check 调度、告警增强决策。

Cox Survival mixed

time_to_incident_forecaster

给定特征，估计指定时间窗内出事的概率。

Stage: stage.risk · 可迁移到 rollback 时机、freeze window、burn-rate 门控。

Minimax BP research

adversarial_policy_arbitrator

面对对抗性 / 竞争性目标时的均衡求解。

Stage: 辅助层 · 目前不在主 hot path，未来用于 feature-vs-SLO 张力仲裁。

5. 机制公式速查

仅罗列最重要的一条公式 + SRE 解释；数学深度见 V1 knowledge_base.html。

#机制核心公式SRE 读法
1TrueSkill $\mu' = \mu + \frac{\sigma^2}{\sigma^2+\beta^2}(r-\mu)$ 服务可靠性的 Kalman 更新
2EOMM $\max_M\ \mathbb{E}[P(\text{Retain}\mid M, H_t)]$ 选保留 SLO 目标概率最大的策略
3Dynamic K $K = K_{\min}+\dfrac{K_{\max}-K_{\min}}{1+e^{\lambda(s-\theta)}}$ 连胜越多，K 越小 → 更不激进
4PCA $X^\top X v = \lambda v$ 遥测降维到可审计的压缩分
5GNN $h^{(l+1)} = \mathrm{ReLU}(W h^{(l)} + \sum A\, h^{(l)} U)$ 依赖图上的消息传递
6Handicap $E_A = \dfrac{1}{1+10^{(\Delta R + P)/400}}$ Elo 期望胜率加 penalty 偏置
7Entropy $H(p) = -p\log_2 p-(1-p)\log_2(1-p)$ 筛掉信息量不足的候选
8Cox Survival $h(t\mid X) = h_0(t)\, e^{\beta^\top X}$ 给定特征的时间窗故障率
9Minimax $\min_y\max_x U(x,y) = \max_x\min_y U(x,y) = v$ 对抗性目标的均衡价值

三重校验（manifest 契约）

  • 名称：必须等于 "retention" / "cox"
  • 形状：weights / beta 的 ndim + dim 严格对齐
  • 契约：extra.feature_names 必须 == EOMM_FEATURE_NAMES / RISK_FEATURE_NAMES

任一失败：artifact 被标为 None，trace.artifacts.validation_errors 记录原因， pipeline 不崩溃，走 bootstrap fallback。

Feature contract 共享

sre/features.py::RISK_FEATURE_NAMES
    = ("loss_streak", "win_streak", "unreliability", "sigma",
       "canary_fraction", "budget_spent")
              │
      ┌───────┴───────┐
      ▼               ▼
training/cox.py     sre/self_iteration.py
(build_observation  (build_risk_feature
 _risk_vector)       _vector)

训练和运行共享一份 NAMES，改动会导致 manifest mismatch → hydrate 被拒。

Replay promotion 门禁

Bootstrap 决策可直接导出 fixture。Fitted 决策需要：

  1. --allow-fitted-artifacts
  2. --artifact-dir 指向 bundle
  3. --artifact-output-dir 归档目录

导出器会 validate_artifact_bundle + archive_artifact_bundle， 写 replay_artifact_manifest.json，fixture 里记 requires_artifact_version。

节点不支持（需外部 DB + 分布式 lease） 多 pod 共享 state 未来工作

K8s 部署硬约束（ADR-0007）

spec:
  replicas: 1             # 硬约束
  strategy:
    type: Recreate        # 滚动更新禁止

F-001 直接影响这一层

目前 LeaseRefreshLoop 续租失败只写 self.error， 无人读取。HTTP server 主循环继续对外服务，另一个 pod 接管 lease 后形成 split-brain。

修复后：失败 → /readyz 返 503 → k8s 自动把流量切走 → pod 重启。 详见 #8 Spec R-001 ~ R-005。

F-002 当前暗坑

Shadow 模式下 gan_decisions_total 反映的是 改写前 的 kind， 但 caller 拿到和 SQLite 里存的都是改写后。告警 "rollback 次数骤增" 会误触发。 修复方案：counter 递增挪到 _shadow_wrap 之后，同时补 decide.shadow_rewritten 日志。详见 #8 R-101 ~ R-105。
