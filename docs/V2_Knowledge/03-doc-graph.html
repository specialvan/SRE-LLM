3 · 文档生命周期

这里回答一个常被忽视的问题：**一份文档什么时候该更新 / 淘汰？**

层次更新触发淘汰条件
V2_Knowledge/ 每轮 review 完成后更新 state.json + 01-current-state 当有 V3 时保留为快照（不删）
claude-review/ 本轮只读，下一轮建新的 claude-review-v3/ 三轮之后可归档到 archive/
knowledge-base.html / deep-dive / equations-digest 代码/方程有重大变化时增量更新 不轻易淘汰（长期价值）
trace-schema / benchmark-metrics / FORMULA_MAP schema bump 时 不淘汰（契约）
codex-handoff.md 每轮更新 不淘汰（始终是"最新交接"）
推荐做法 每轮 review 建独立子目录（claude-review-v3/, gpt-review-v4/），不覆盖前轮内容。 V2_Knowledge/ 作为"最新入口"快照；当前目录升级到 V3 时把现有的移到 V2_Knowledge_archived/。
