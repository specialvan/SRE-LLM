Z1Architecture at a glance

一张图看懂整个系统的 7 层。每一层只 收紧 下层决策，不反向污染。

一条典型 tick 的完整数据流

metrics → L1 read_context → L3 z-score → L4 AdaptiveCombiner → L6 ContractionAware → L6 LearnedEnvelope → actuator ↑ │ └──── audit trail (L2) ← ingest(action, context, delta) ← feedback from plant ────────────────────┘

关键约束：L6 的 envelope 只能更紧，不能自动更松（relax() 是唯一放松路径，L7 人为操作）。 L4 的 learner 只能调 bias，不能突破 L2 的 floor/ceiling 硬约束。 L3 的观测者不修改任何决策。详见 Z5 不变量。

Jump to deeper content: detailed-architecture.md 里有逐层的 API 契约、 invariant enforcement sequence 和 per-tick 伪代码。

如何"意外"破坏 invariants（以及防范）

常见错法 1：把 Σa=1 降级成损失项
  loss += λ·(Σa-1)²
后果：非平稳输入下会出现 Σa≠1 的周期性超发/欠发。
防范：I-01 / I-03 的 regression test 会失败。
常见错法 2：在 fit() 里直接赋值放宽
  self.current_high = proposed_hi # 没有 np.minimum
后果：envelope 可能因偶然的 SAFE 样本放宽，破坏 ratchet 语义。
防范：I-05 的 regression test 会失败。
常见错法 3：learner 覆盖运维 bias
  spec.bias = float(lg) # 未加 static_bias
后果：运维在 SignalSpec(bias=...) 里配的先验被悄悄抹掉。
防范：test_adaptive_combiner_preserves_static_bias_under_learning 会失败。
常见错法 4：streaming cursor 在报错时也前进
  except: self.cursor.offset = next_offset # 跳过了坏 JSON
后果：事故日志被默默吞掉，审计链断裂。
防范：I-10 的 regression test 会失败。处理方案见 AI-4（加 opt-in 的 skip_bad_lines）。
黄金法则：如果你要修改任何一个 current_* 字段或任何以 _project_ 开头的函数，先跑 pytest -q 基线 → 改代码 → 再跑一次。如果测试数从 174 降下来，停下来看看你是不是撞了不变量。

GLGlossary & external references

术语表

AttnResAttention Residual；纵向层间 softmax 加权残差
Σa=1softmax 归一化后权重之和恒为 1（信息守恒）
floor / ceiling每个 signal 的权重上下界（硬约束）
ratchet棘轮；envelope 只能自动收紧，不能自动放松
relax()运维手动放宽 envelope 的唯一 API
quorum触发 envelope 收紧所需的最少 UNSAFE 证据质量
hysteresis收紧时保留的余量，避免边界抖动
OutcomeEvidence(safety_score, confidence) 形式的软标签
FTRLFollow-The-Regularized-Leader；Hedge 是其负熵正则特例
Hedgemultiplicative weights update，O(√(T ln n)) 后悔界
credit时间信用分配；事故后给每个 signal 归因
shadow影子运行；新控制器与 baseline 并行、不下发动作
counterfactual反事实解释；屏蔽某 signal 后重算决策
drift (KL/W1)权重漂移检测；KL 捕塌缩，W1 捕平移
contraction残差雅可比收缩性判据；gain > 1 → 正反馈告警
ADRArchitecture Decision Record；破坏 invariant 前必写
