1 · 使用方式

这份文档是 knowledge-base.html 的颗粒度下沉版，目的是让人/Codex 可以逐函数、逐行地理解系统行为， 不再停留在"这一模块做什么"而是"这一模块的每一个分支在做什么、为什么这样做、何时会出错"。

重点做了三件事：

  1. 把每个模块的输入输出契约形式化（precondition / postcondition / invariant）。
  2. 把算法步骤用伪代码逐行标注，每一步写"why"而不只是"what"。
  3. 把失败模式按 "输入异常 → 内部状态异常 → 输出路径 → 降级动作" 整理成矩阵。

每个模块末尾的 SRE 挂钩 给出本模块最可复用的抽象，在 sre-adaptation.html 里展开。

3 · 模块 1 · 交互意图图 InteractionIntentGraph

核心问题

把"谁影响谁、影响多大"表达成一个加权有向图；每帧根据几何 + 意图更新。

契约

IN
一组 Node：{id, type, pos∈ℝ², vel∈ℝ², intent∈P(5)}
OUT
加权有向图 {(src, dst) → w∈[0,1]}
PRE
节点 id 唯一；intent 是非负分布（可未归一化）
POST
边权单调：dist ↑ ⇒ w ↓；conflict ↑ ⇒ w ↑
INV
① 无自环；② w < EPS 的边被剪枝；③ 重建而非增量（避免陈旧边）

3.2 算法步骤（update() 伪代码 + why）

def update(self):
    self._edges.clear()                         # ① 重建语义：避免陈旧边留存（比如 agent 已离开）
    for i, ni in enumerate(self._nodes.values()):
        for j, nj in enumerate(self._nodes.values()):
            if i == j: continue          # ② 无自环
            w = self._edge_weight(ni, nj)     # ③ 核函数在下面拆解
            if w >= self.EPS:                # ④ 小权重剪枝 —— 下游势能求和的开销由此有界
                self.add_edge(Edge(ni.node_id, nj.node_id, w))

def _edge_weight(i, j):
    d       = ‖j.pos − i.pos‖                         # 欧氏距离，单位 m
    dist_k  = exp(−d / D0)                             # ⑤ 指数核，保证 w∈[0,1] 且连续无奇点
    if rnorm < 1e−6 or ‖i.vel‖ < 1e−6:
        heading = 0.5                                  # ⑥ 退化：无法算朝向时给中性值
    else:
        cos_t = (i.vel · (j.pos − i.pos)) / (‖i.vel‖ · rnorm)
        heading = 0.5·(cos_t + 1)                      # ⑦ 映射到 [0,1]：朝对方跑比跑开影响大
    conflict = intent_conflict(i.intent, j.intent)     # ⑧ 下面拆解
    return dist_k · heading · conflict                # ⑨ 乘积形式 —— 任一因子为 0 即断开

def intent_conflict(p_i, p_j):
    total = 0
    for a, pa in p_i.items():
        for b, pb in p_j.items():
            total += pa · pb · C_TABLE.get((a,b), 0.1)   # ⑩ 未知组合给 0.1 保守先验
    return clamp(total, 0, 1)                          # ⑪ 双重保险
关键设计决策（为何不这样做）
  • 为何不用 1/d 作为距离核？ 因为 d→0 时发散，会让下游 $\Phi$ 或 CBF 拿到无穷值，数值不稳。指数核有界且处处可导。
  • 为何乘积而不是加权和？ 加权和在任一因子为 0 时仍可能贡献；乘积让"距离远"或"意图完全兼容"时天然置零，符合语义。
  • 为何每帧重建？ 增量更新需要跟踪"哪些 agent 已离场"这类元数据，实现复杂度高；O(n²) 重建在 n≤100 量级远低于感知流水的成本，不是瓶颈。
  • 为何对未知冲突给 0.1？ 比 0 保守（不忽略未知威胁），又比 1 不过激（未知不等于冲突）。

4 · 模块 2 · 车辆动力学 BicycleModel

核心问题

给定当前状态与输入，产生一步后的状态；保证永远不越摩擦 / 速度包络。

契约

IN
State (px,py,ψ,v,a,μ), Control (δ,j), dt≤0.1s
OUT
新 State
PRE
μ∈(0,1.2], v≥0, |a|≤μ·g（由前次 step 保证）
POST
新 state 仍满足所有 PRE；v∈[0, v_max]
INV
clamp 发生在两处：f() 内 jerk clamp + step() 末端状态 clamp（双保险）

4.1 RK4 与 clamp 的双层防护

4.2 单步积分伪代码

def step(state, u, dt):
    x0 = state.to_vec()                              # ndarray(6)
    def _eval(xv):
        return self.f(State.from_vec(xv), u)
    k1 = _eval(x0)
    k2 = _eval(x0 + 0.5·dt·k1)
    k3 = _eval(x0 + 0.5·dt·k2)
    k4 = _eval(x0 + dt·k3)
    x1 = x0 + dt/6 · (k1 + 2k2 + 2k3 + k4)

    a_cap = x1[5] · G                                  # μ·g, μ 本身不变（x1[5]==x0[5]）
    x1[4] = clip(x1[4], −a_cap, a_cap)                # ③ 加速度 clamp
    x1[3] = clip(x1[3], 0, v_max)                     # ③ 速度 clamp
    return State.from_vec(x1)
为何 jerk 作为输入，而不是 acceleration？

因为 CBF 在刹车距离 barrier 上需要做到 相对度 1。考察 $h = d - v·τ - v²/(2a_\text{brk})$：

$$ \dot h = \nabla_p d \cdot \dot p - τ\dot v - \frac{v\dot v}{a_\text{brk}} = -v\cos\theta - (τ + v/a_\text{brk})\,a $$

$a$ 在状态里、受 $\dot a = j$ 驱动。如果让 acceleration 直接作为输入 $u=a$，则 $a$ 是代数变量、命令切换会瞬断， 不符合真实执行器（线控刹车/油门有速率限制）。把 $a$ 放进状态、让 $j$ 作为输入，命令连续可导， barrier 的 $\dot h$ 就对 $u$ 不再有"紧急切换"导致的不连续。

4.3 非欧流形判定 Manifold.is_feasible

def is_feasible(state):
    if state.v < −0.01 or state.v > v_max·1.05: return False   # ① 速度包络
    if |state.a| > μ·g + 1e−3: return False                      # ② 摩擦包络
    for obs in obstacles:
        if obs.signed_distance(state.px, state.py) < 0:               # ③ void 判定
            return False
    return True

三项构成"连续层的合法子集"。注意这里的 1e-3 / 1.05 是诊断阈值，比 clamp 宽一点以容忍数值误差；真正的约束由 clamp 保证。

4.4 失败矩阵

异常路径后果缓解
μ=0（冰面）a_cap=0 → 任何 jerk 都被 clamp 到 0车辆不能加减速正确行为；上层 planner 应在低 μ 时放弃追赶目标速度
dt 被意外放大（调度抖动）RK4 误差 O(dt⁵) 放大状态偏差planner 主环限 dt≤0.1；超时进入降级（L2）
感知 μ 错误友好 clamp 但所有 CBF 低估刹车距离撞derating + μ_residual 监视（见 R-02）
steer NaN（上游 bug）np.tan(NaN)=NaN状态污染入口 clip(u.steer, ±max_steer) 已挡 NaN？不，clip 对 NaN 穿透 → 需要额外 NaN 检查
待修 np.clip(NaN, lo, hi) 仍返回 NaN。建议在 BicycleModel.f 入口加 if not np.isfinite(u.steer) or not np.isfinite(u.jerk): return zeros(6)； 这是个不大但安全敏感的补丁，列入 PR-1.2-03-nan-guard。
SRE 挂钩
抽象 "输入 → 两重 clamp → 输出" 是一个可复用模式：把任何物理/业务不等式表达成"调用时钳位 + 末端钳位"的双层防护。 在 SRE 里对应"客户端 timeout 裁剪 + 服务端 deadline 裁剪"，也是双保险。详见 sre-adaptation §4。

5 · 模块 3 · 势能场 PotentialField

核心问题

把目标 / 障碍 / 交互三类诉求合成一个标量场 $\Phi$；给下游名义策略一个物理可解释的方向。

契约

IN
state, manifold, graph, ego_id
OUT
value(x) → float, grad_xy(x) → ℝ², flow_direction(x) → ℝ² (unit)
PRE
三项权重非负；goal 是 2D 点
POST
梯度数值有界（因 obstacle_potential 使用 max(d, 0.05) 下限）
INV
安全半径外 obstacle 项 ≡ 0（有限支集）

三项的设计张力

项形式作用范围常见病态对策
吸引$\tfrac12 w_g\|p-p_g\|^2$全局距离大时梯度过大，推翻其他项小 $w_g$（默认 1.0，demo 里降到 0.05）
排斥$w_o(r_s/d-1)^2·\mathbb{1}[d<r_s]$有限 $r_s$U 形障碍产生局部极小上层做全局路径，$\Phi$ 只做局部
交互$w_i\sum w_{ij}/d_{ij}$由 $G_I$ 决定边权抖动 → 梯度抖动EMA 平滑 $p_i$

梯度的数值实现

默认用二阶中心差分的简化版（前向差分）：

$$ \frac{\partial\Phi}{\partial p_x} \approx \frac{\Phi(p_x+\epsilon, p_y) - \Phi(p_x, p_y)}{\epsilon}, \quad \epsilon = 10^{-3} \text{ m} $$

在 2D 平面上每帧只做 2 次 $\Phi$ 求值，< 50 μs。为什么不一次求解析梯度？ 因为 obstacle 项在 $d=r_s$ 处有不连续切换（𝟙[d<r_s]）， 解析梯度要按分支写，调试成本高；数值差分虽然有 $O(\epsilon)$ 误差，但下游 CBF 会兜底硬约束，梯度只做"方向建议"而非"量化命令"。

常见陷阱 obstacle_potential 使用 max(d, 0.05) 防止 $d→0$ 发散。但这同时会让 "贴近障碍时梯度渐趋于常量"—— 在非常接近障碍时，势能梯度已经不能把车推开了，这是交给 CBF 硬拦的原因。结论：$\Phi$ 是"软建议"，硬约束只能靠 CBF。
抽象 这是典型的 "多目标加权合成 + 局部梯度启发"。 SRE 里做 QoS 调度 / 自动调参可以复用： 把"成本 / 延迟 / 可用性"三项合成一个 $\Phi$，名义策略沿 $-\nabla\Phi$ 走； CBF 兜"错误率 < 阈值"这类硬约束。详见 sre-adaptation §5。

6 · 模块 4 · Lyapunov 稳定性 QuadraticLyapunov / StabilityMonitor

核心问题

给系统装一个"能量计"$V(x)$：只要任何控制命令让 $\dot V$ 超标，就认为动力学上不稳定。

契约

IN
state, u, dynamics, manifold, target_speed, dt
OUT
check()→(stable:bool, dV_dt:float); metrics()→dict
PRE
dt ∈ (0, 0.1]; target_speed ∈ [0, v_max]
POST
V(x^*)=0, V(x)≥0, 连续
INV
V 只反映稳定性；安全由 CBF 管 —— 两者数学解耦

为什么 V 里不含距离项 —— 工程踩坑实录

原文措辞上把"车辆安全距离"也塞进 $V$。第一版实现跟着这样做：

$$ V_{\text{bad}}(x) = \tfrac12 q_v (v-v^*)^2 + \frac{q_d}{\max(d_\min, \epsilon)^2} $$

结果：车辆朝目标前进 → 最近障碍距离变小 → $V$ 单调上升 → T_inv 判定不稳定 → 每一步都刹。Demo 里打印出 "emergency_brake steps: 150/150"。

诊断：$V$ 把两个物理意义不同的量耦合成一个代数式，导致 Lyapunov 的"能量下降"语义被污染——接近障碍不等于能量上升。

修复（当前版本）：

$$ V(x) = \tfrac12 q_v (v - v^*)^2 $$

一个纯速度跟踪项。距离的硬约束完全移到 CBF。这呼应原文 §2 说的"Lyapunov = 物理红线 / CBF = 拓扑栅栏"的职责分工—— 工程落地上必须严格解耦。

$\dot V$ 的数值实现

def dV_dt(state, u, dynamics, manifold, target_speed, dt=0.01):
    v0 = V_full(state, manifold, target_speed)       # 当前能量
    s1 = dynamics.step(state, u, dt)                  # 前向积分一步
    v1 = V_full(s1, manifold, target_speed)          # 下一步能量
    return (v1 − v0) / dt                            # 前向差分

为何 dt=0.01 而不是 planner 的 0.1？ 较小的 dt 让差分更贴近真导数；但太小会进入 jerk 尚未累计影响 v 的"盲区"。0.01 是经验甜点：jerk 对 $\dot V$ 的影响已经显形（$\Delta v \approx j \cdot dt^2 / 2 \sim 3\times 10^{-4}$ m/s 仍可测），同时噪声可控。

StabilityMonitor 与 T_inv 的状态机协作

SRE 挂钩 抽象 Lyapunov 的核心模式是 "定义一个单调下降的量 → 监视其导数 → 违反时矫正"。 SRE 里对标：定义 "错误预算消耗率"（如 error budget 的瞬时 burn rate），监视它是否超过衰减目标，超标时自动降级 feature flag / 限流。 见 sre-adaptation §6。

7 · 模块 5 · 可达集 ReachableSet / DeadZoneDetector

核心问题

在 $T$ 秒内车辆能去哪里？当威胁落在"去不到的地方之外"时就是逻辑死区——提前告警。

契约

IN
state0, horizon T, n_samples N, dt
OUT
endpoints: ℝᴺˣ²; hull_vertices: ℝᴹˣ²; in_reachable(target): bool
PRE
T ∈ (0, 5], N ∈ [50, 500]
POST
hull 包络 endpoints；事件驱动，不在每帧主环调用
INV
凸包 乐观高估：hull ⊇ 真实可达集；只可作为"不可达"的下界证明，不可作为"可达"的保证

采样策略的选择

方案覆盖率N 敏感度选中？
均匀随机（当前）一般中✓ 实现最简
Latin Hypercube较好低可替换，scipy 可用
Sobol 低差序列最好低推荐演进方向
极值采样（bang-bang）包络最优极低最适合可达集；未实现

为什么采用"分段常值、一次切换"而不是"每步随机"？

steer1, steer2, jerk1, jerk2 = uniform(...)    # 每条轨迹 2 套参数
half = steps // 2
for t in range(steps):
    if t < half: controls.append(Control(steer1, jerk1))
    else:        controls.append(Control(steer2, jerk2))

原因：实际执行器有带宽限制（转向与加速度不会每 0.1 s 翻转），每步随机会模拟出真实系统去不到的轨迹， 凸包会乐观放大。用"分段常值 + 一次切换"是在可达集乐观程度与算法简单性之间的折中。

DeadZoneDetector 的最坏情况构造

def check(state, threat_pos, threat_vel):
    # 最坏情况：自车全力刹（最保守），他车匀速（最坏轨迹假设）
    controls = [Control(0, −jerk_max)] · steps
    traj = dynamics.rollout(state, controls, dt)
    for i, s in enumerate(traj):
        tp = threat_pos + threat_vel · (i·dt)
        clear = ‖(s.px, s.py) − tp‖
        min_clear = min(min_clear, clear)
    return (min_clear < 0, min_clear)

注意：这里的"最坏"是非对称假设——对自己保守（全力刹）、对对方激进（匀速撞来）。在不确定性博弈下这等价于假设对方"最不配合"，与 §2.3 的最坏情况纳什思想一致。

SRE 挂钩 抽象 可达集是 "容量 / 预算的前瞻性证明"——"未来 T 秒内我能做到什么"。 SRE 里对标："未来 5 分钟内系统能处理的流量上限"（基于 auto-scaling 速率 × 实例预热时间）。 当预估负载超出此集合，提前触发 graceful shed / 拒绝路径。 详见 sre-adaptation §7。

8 · 模块 6 · CBF-QP CBFQPFilter

核心问题

把任何安全建议（"离障碍要远"、"车道别出"）表达成一个数学不等式 $\dot h + \alpha h \ge 0$， 再解一个 QP 把名义命令投到"不违反任何不等式"的最近点。

契约

IN

8.1 刹车距离 barrier 推导（工程扩展）

原论文直接用"距离 barrier"$h=d-r_s$。但这对 jerk 驱动系统 相对度 = 2，一次 QP 无法收敛。工程上必须自己造一个相对度 1 的 barrier：

推导

考虑 ego 沿 $+x$ 方向以速度 $v$、加速度 $a$ 运动，目标是"碰前刹停"。若施加常值减速 $a_\text{brk}$，刹停距离为 $v^2/(2a_\text{brk})$； 但 jerk 驱动意味着 $a$ 不能瞬时切换，需要约 $\tau = |a-(-a_\text{brk})|/j_\text{max}$ 秒 ramp，期间已走 $v\tau$。

$$ h_\text{brake}(x) = d_\text{obs}(p) - r_s - v\tau - \frac{v^2}{2a_\text{brk}(\mu)} $$

对时间求导（忽略 $\mu$ 缓变）：

$$ \dot h = -v\cos\theta - \tau \dot v - \frac{v\dot v}{a_\text{brk}} = -v\cos\theta - \left(\tau + \frac{v}{a_\text{brk}}\right)\cdot a $$

$a$ 在状态里，$\dot a = j$，因此 $\dot h$ 不直接依赖 $u$——相对度还是看起来像 2？ 这里的关键是："QP 选 $u$ 后，用 h_dot_horizon=0.1s 的有限差分估计 $\dot h$"， 把 $a$ 在 horizon 内的累积变化 $\Delta a \approx j\cdot \text{dt}$ 纳入进来——这才是工程上让 jerk 直接影响 $\dot h$ 的真相。

$a_\text{brk}(\mu)$ 的 μ 自适应
$$ a_\text{brk}(\mu) = \text{safety} \cdot \min(a_\text{max}, \mu g), \quad \text{safety}=0.6 $$

双限：执行器上限 $a_\text{max}=6$ m/s²；路面摩擦 $\mu g$；再乘 0.6 的 derating 吸收 $\mu$ 估计误差。μ=0.5 的雨天自动得到 $a_\text{brk}\approx 2.9$ m/s²，刹车距离拉长 1.7 倍，CBF 更早开始刹。

8.2 网格搜索 vs 真 QP

本实现用二级网格搜索替代 QP，避免引入 OSQP 等外部依赖。

# 粗网格
best_u = None, best_cost = ∞
for s in linspace(steer_lo, steer_hi, 11):
    for j in linspace(jerk_lo, jerk_hi, 11):        # 121 个候选
        u = Control(s, j)
        cost, ok = _objective(state, u_nom, u)
        if ok and cost < best_cost:
            best_u, best_cost = u, cost
# 精化：在 best_u 周围一格里再搜 21×21
s0, j0 = best_u
ds, dj = (hi-lo)/11
for s in linspace(s0-ds, s0+ds, 21):
    for j in linspace(j0-dj, j0+dj, 21):        # 441 个候选
        ...
# 最终 562 次 barrier 评估 · 每次 ~10 µs → 6 ms
为什么还可以接受？
  • 2D 控制空间足够小，网格覆盖密度够（精化步距 < 1% 包络）。
  • 每个候选的 cost 计算是纯向量运算，可以 numpy 矢量化到一次调用（未来优化）。
  • 网格不可行时明确的 fallback（刹停）比 QP 求解器不收敛更好调试。
什么时候必须换 QP？
  • barrier 数 > 10：穷举仍然 ok，但随 barrier 数线性上升。
  • 控制维度 > 2：每加一维网格点数乘 10，立刻退化。本工程 (δ, j) 是 2D 的恰好位于可接受边缘。
  • 需要提供 dual 信息做约束灵敏度分析：真 QP 给出 Lagrange 乘子，网格法没有。

8.3 相对度分析：为何 DistanceBarrier 不够

SRE 挂钩 抽象 CBF-QP 的骨架是 "名义建议 + 若干不等式约束 → 求最近可行解"。 SRE 里对标："客户端想发 1000 QPS，但必须满足 cache 命中率≥95%、CPU≤70% …… 求能满足所有 SLO 的最近流量上限"。 这就是 admission controller 的数学底子。详见 sre-adaptation §8。

9 · 模块 7 · T_inv 算子 ControlInvariantOperator

核心问题

把"任何可能违反 Lyapunov 的名义命令"矫正成"一定不违反"。是整个系统的最后一道闸。

契约

IN
state, u_nn
OUT
u_safe ∈ U; info{V, dV_dt, status ∈ {stable, relaxed_exp, relaxed, non_increasing, emergency_brake}}
PRE
下游 CBF 已跑过一次（保证 barrier 已经折叠）
POST
返回的 u_safe 保证 $\dot V(x, u_\text{safe}) \le \tau$（τ=1e-3），或 status=emergency_brake
INV
有限步终止（最多 relax_steps+1 次评估）；绝不抛异常

9.1 正确性不变式（评审要点）

I-01 · 终止性 松弛过程每次 jerk ← jerk − j_max/N，单调下降，最多 N 步达到 jerk = -j_max。 此时命令等价于 fallback，fallback 永远满足 Lyapunov（速度下降，$V$ 下降）。故算法必然终止。
I-02 · 安全性 若 status ∈ {stable, relaxed_exp, relaxed, non_increasing}：$\dot V \le \tau$。 若 status = emergency_brake：执行 $u=(0, -j_\max)$，对应 $a$ 单调变负、$v$ 单调下降、$V = \tfrac12 q_v(v-v^*)^2$ 的导数 $q_v(v-v^*)a$。 注意当 $v < v^*$ 时 $(v-v^*) < 0$、$a < 0$ → $\dot V > 0$，此时 Lyapunov 反而上升——这是 emergency_brake 的已知折中： 宁可暂时不稳定（偏离目标速度）也不撞。故 emergency_brake 是超越 Lyapunov 约束的兜底。
I-03 · 有界性 返回的 u_safe 满足执行器约束：|steer|≤max_steer, |jerk|≤jerk_max。 这由下游 CBF 的 grid 范围保证（见 §8.2）+ fallback 显式构造。
I-04 · 观测完备性 任何一次 apply 必然写 info 四字段。status 是外部 SLI（emergency_brake 计数）。不允许静默成功。

9.2 关键代码段的逐行标注

def apply(state, u_nn):
    u_cbf, cbf_info = self.cbf.filter(state, u_nn)      # (1) 先过 CBF：折叠可行集
    V = self.stability.fn.V_full(state, ...)           # (2) 当前能量
    exp_target = −self.gamma · V                        # (3) 指数衰减目标 dV/dt ≤ −γV

    u = u_cbf
    info = {"cbf": cbf_info, "V": V, "dV_dt": None, "status": "unchanged"}

    def _dv(cand):
        return self.stability.fn.dV_dt(state, cand, ...)

    dv = _dv(u)
    info["dV_dt"] = dv

    # (4) 快车道：已经稳定
    if dv ≤ self.tol:
        info["status"] = "stable" if dv ≤ exp_target + 1e-6 else "non_increasing"
        return u, info

    # (5) 松弛循环：逐步降 jerk
    best_u, best_dv = u, dv
    for step in range(self.relax_steps):
        new_jerk = max(u.jerk − j_max/N, −j_max)         # 单调下降 → I-01 终止性
        u = Control(u.steer, new_jerk)
        dv = _dv(u)
        if dv < best_dv: best_u, best_dv = u, dv
        if dv ≤ exp_target + 1e-6:                        # 最优出口
            info["dV_dt"] = dv
            info["status"] = "relaxed_exp"
            return u, info
        if dv ≤ self.tol:                                 # 次优出口
            info["dV_dt"] = dv
            info["status"] = "relaxed"
            return u, info

    # (6) 松弛耗尽：取最优中间结果
    if best_dv ≤ self.tol:
        info["status"] = "relaxed"
        return best_u, info

    # (7) 真正的降级 —— I-02 的"兜底"分支
    brake = Control(0.0, −j_max)
    dv_brake = _dv(brake)
    info["dV_dt"] = dv_brake
    info["status"] = "emergency_brake"
    return brake, info

10 · 模块 8 · 博弈 / 安全冗余 BeliefState / WorstCaseGame

核心问题

把"我不知道你要干什么"这种信息不完备翻译成"多留一车位"这种几何缓冲。 本模块不产生命令，而是改 CBF 的 safety_margin——博弈层的不确定性被"代数化"到几何层。

契约

IN
BeliefState.distribution: dict[intent→prob]; rel_speed
OUT
safe_buffer(rel_speed, belief) → float (meters)
PRE
distribution 非负；上游归一化
POST
$r_\text{buf} \ge r_\text{base}$；关于 entropy 单调不减；关于 rel_speed 单调不减
INV
最坏情况聚合：aggregate_buffer = max over opponents

为何是加性而不是乘性？

$$ r_\text{buf} = r_\text{base} + k_v \max(v_\text{close}, 0) + k_\eta \cdot \eta $$

加性的好处：线性可解释——"意图不确定给我加了 2m、对方开得快给我加了 3m"。 乘性会让低闭合速度 + 高熵变成"0 × large = 0"的漏洞。 代价：极端情况 buffer 可能过大，但这是安全方向的过保守，可接受。

熵的归一化

$$ \eta = \frac{H(p)}{\log |p|} = \frac{-\sum p_k \log p_k}{\log |p|} \in [0, 1] $$

用归一化熵而非原始熵，这样 belief 的类别数不影响 $k_\eta$ 的解读——$\eta=0.5$ 永远意味着"一半不确定性"，无论类别是 4 还是 10。

与 CBF 的耦合接口

# planner 初始化时

  • 在 StructuralPlanner.step 里加一行 self.cbf.barriers = make_obstacle_barriers(..., margin=r_buf)。
  • 或者给 BarrierFunction 协议加 safety_margin 属性（避免重建对象）。
SRE 挂钩 抽象 这就是 "用不确定性度量驱动安全余量"。 SRE 对标：上游监控抖动大（observability entropy高）时，自动加大 SLO 余量： 例如 "错误率 P99 波动大 → 自动把限流阈值从 95% 降到 85%"。 详见 sre-adaptation §10。

step() 的精确流程

def step(state, graph, dt):                     # 外部唯一入口
    u_nn = self.nominal(state, graph)                 # (1) 名义策略：可替换点 ★
    u_safe, info = self.t_inv.apply(state, u_nn)       # (2) CBF + Lyapunov 矫正
    next_state = self.dynamics.step(state, u_safe, dt)  # (3) 应用到动力学

    trace = {                                        # (4) 可观测性
        "u_nn":  [u_nn.steer, u_nn.jerk],
        "u_safe": [u_safe.steer, u_safe.jerk],
        "state": state.to_vec(),
        "next_state": next_state.to_vec(),
        "min_dist": self.manifold.min_distance(state),
        "V": info["V"],
        "dV_dt": info["dV_dt"],
        "status": info["status"],
        "cbf_status": info["cbf"]["status"],
    }
    return next_state, u_safe, trace

注意 graph 更新不在这里——是调用者的职责。这让"感知→意图图更新"与"决策→step"可以在不同线程/不同频率跑。
